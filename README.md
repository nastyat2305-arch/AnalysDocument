#  AnalysDocument — Простой анализатор ГОСТов и ТУ

> Учебный проект, 1 курс. Команда «Сыр» 🧀

Программа сравнивает ваши технические документы (ГОСТ, ТУ, ТК, ТИ и др.) с эталонными нормативами: **ТР ТС 021/2011** (безопасность пищевой продукции) и **МР 2.3.0279-22** (производственный контроль).

**Что находит:**
-  **Противоречия** — если в вашем документе цифры или условия не совпадают с эталоном
-  **Пропуски** — если в документе нет обязательных требований из эталона
-  **Структурные ошибки** — если не хватает нужных разделов
-  **Метаданные** — собирает информацию о файле и документе для прозрачности анализа

## 🔧 Что делает каждый модуль (простыми словами)

### `main.py` — «Дирижёр»
- Показывает меню в консоли
- Загружает настройки (API-ключ, модель)
- Запускает загрузку эталонов и анализ файлов
- Координирует работу всех остальных модулей

**Главные функции:**
- `load_etalons()` — читает эталонные файлы, разбивает их на части, векторизует и сохраняет в кэш
- `analyze_file()` — загружает ваш документ, собирает метаданные, сравнивает с эталонами, возвращает результат
- `run_batch()` — обрабатывает несколько файлов параллельно (быстрее!)
- `main()` — цикл меню, обработка выбора пользователя

---

### `file_loader.py` — «Загрузчик файлов»
- Читает текстовые файлы (.txt) и .docx
- Определяет тип документа по названию или первым строкам

**Функции:**
- `load_document(filepath)` — возвращает текст из файла
- `detect_document_type(filename, text)` — угадывает: ГОСТ, ТУ, ТК, ТИ, МУ и т.д.

---

### `metadata_extractor.py` — «Сборщик метаданных»
- Считывает базовые свойства файла: размер, тип, дата создания/изменения
- При возможности вытягивает внутренние метаданные документа (автор, версия, дата утверждения, ответственный)
- Сохраняет всё в отчёт, чтобы вы видели, **с каким именно файлом** работал анализатор

**Функции:**
- `extract_metadata(filepath)` → `dict` — возвращает словарь с техническими и документными метаданными
- `_parse_docx_props(docx_path)` — читает встроенные свойства `.docx` (автор, дата правки, компания)
- `_clean_metadata(raw_meta)` — убирает пустые поля, приводит даты к единому формату, добавляет пометки о точности

---

### `text_splitter.py` — «Разделитель текста»
- Делит большой документ на небольшие смысловые блоки (~800 символов)
- Добавляет к каждому блоку «метки»: к какой теме относится (микробиология, химия, упаковка и т.д.) и какие есть цифры

**Функции:**
- `split_into_chunks(text)` — возвращает список блоков с текстом, метками и числовыми данными
- `_extract_domain_hints(text)` — ищет ключевые слова, чтобы понять тему блока
- `_extract_numerical_context(text)` — вытаскивает цифры с единицами измерения (например, «25 °С», «0,5 мг/кг»)

---

### `embedder.py` — «Векторизатор»
- Превращает текстовые блоки в числа (векторы), чтобы компьютер мог сравнивать их по смыслу
- Сохраняет результаты в папку `cache/`, чтобы не пересчитывать при следующем запуске

**Класс и функции:**
- `EmbeddingEngine` — синглтон (один экземпляр на всю программу), загружает модель `all-MiniLM-L6-v2`
- `embed_chunks(chunks, doc_id)` — векторизует список блоков, использует кэш если есть
- `find_top_k_matches(query_emb, corpus_embs, k)` — находит `k` самых похожих блоков в эталоне (порог схожести 0.35)

---

### `comparator.py` — «Сравниватель» (ядро AI)
- Берёт блок из вашего документа, находит похожие блоки в эталоне
- Отправляет пары «эталон ↔ ваш документ» в большую языковую модель (LLM) с запросом: «Есть ли тут противоречия или пропуски?»
- Фильтрует нерелевантные пары до отправки в AI (экономит токены и время)

**Класс и функции:**
- `AIComparator` — обёртка над OpenAI-совместимым API, управляет запросами и повторными попытками
- `analyze_pair(ref_chunk, doc_chunk)` — отправляет одну пару в LLM, получает JSON с результатом
- `batch_analyze(ref_chunks, doc_chunks, ref_embs, doc_embs)` — обрабатывает все блоки документа параллельно
- `_domains_compatible()` — проверяет, можно ли сравнивать два блока (например, микробиологию не сравниваем с упаковкой)
- `_numerical_context_match()` — сверяет цифры с учётом единиц измерения и допусков

---

### `structure_analyzer.py` — «Проверка структуры»
- Отправляет весь документ в LLM с вопросом: «Есть ли все обязательные разделы для этого типа документа?»
- Возвращает список недостающих разделов

**Функция:**
- `analyze_structure_ai(client, model, text, doc_type)` — анализирует структуру, возвращает список замечаний

---

### `report_generator.py` — «Генератор отчётов»
- Форматирует результаты анализа для вывода в консоль (цветной текст, таблицы)
- Сохраняет отчёт в файлы: `.json` (для программ) или `.txt` (для чтения)
- Включает в отчёт собранные метаданные, чтобы вы видели версию файла, дату правки и автора

**Функции:**
- `format_console_report(filename, doc_type, trts_result, mr23_result, meta)` — готовит красивый вывод для терминала
- `save_report(reports, filename, format)` — сохраняет один или несколько отчётов в файл

## 💡 Как это работает (коротко)

```
1. Подготовка эталонов (один раз):
   ├── Читаем trts21.txt и mr23.txt
   ├── Делим на блоки, добавляем метки
   └── Превращаем в векторы → сохраняем в cache/

2. Анализ вашего документа:
   ├── Загружаем файл, собираем метаданные (размер, даты, автор)
   ├── Определяем тип (ГОСТ, ТУ...)
   ├── Делим на блоки, векторизуем
   ├── Для каждого блока ищем 3–5 самых похожих в эталоне
   ├── Отправляем пары в AI: «Сравни, есть ли проблемы?»
   ├── Парсим ответ, собираем противоречия и пропуски
   └── Отдельно проверяем структуру документа

3. Результат:
   ├── Показываем в консоли: что найдено, где проблемы
   ├── Добавляем метаданные в начало отчёта
   └── Сохраняем в JSON/TXT для дальнейшей работы
```



## ❗ Ограничения (честно)

> [!WARNING]
> Проект учебный, поэтому есть нюансы:

- Программа сравнивает узкий ГОСТ с рамочным регламентом → могут быть «лишние» замечания к другим продуктам. Смотрите на контекст.
- Точность зависит от качества эмбеддингов. Модель `all-MiniLM-L6-v2` быстрая, но для сложных случаев можно заменить на `paraphrase-multilingual-mpnet-base-v2` (требует больше памяти).
- Метаданные `.docx` читаются только если файл сохранён с встроенными свойствами. В `.txt` доступны только системные данные (размер, даты ОС).
- Нужен доступ к интернету для запросов к AI (если не используете локальную модель через Ollama).
